## 1. 소개 (Introduction)
본 패킷 스니퍼는 정보보호학 연구 및 시큐어 코딩 교육용으로 설계되었습니다. 파이썬의 핵심 네트워크 분석 라이브러리인 **Scapy**를 활용하며, 터미널 상에서 실시간으로 흐르는 이더넷 프레임, IP 패킷, TCP/UDP 세션, DNS 질의, HTTP 평문 페이로드를 파싱하고 시각화합니다.

---

## 2. 실행 전 준비 사항 (Prerequisites)

### 가상환경 설정 및 의존성 설치
이미 가상환경과 의존성이 설치되어 있습니다. 수동으로 다시 설정해야 하는 경우 아래 명령어를 사용합니다.
```bash
# 1. 가상환경 생성
python3 -m venv .venv

# 2. Scapy 의존성 설치
.venv/bin/pip install scapy
```

### 권한 요구사항 (macOS BPF)
*   **중요**: macOS에서 Raw 패킷을 스니핑하려면 BPF(Berkeley Packet Filter) 디바이스 디바이스 노드(`/dev/bpf*`)에 접근해야 합니다.
*   일반 사용자 계정으로는 권한이 제한되므로, 실행 시 항상 **`sudo` (관리자 권한)**를 접두사로 붙여 주어야 합니다.

## 3. 도구 실행 방법 (How to Run)

### 1단계: 프로그램 실행
프로젝트 루트 디렉터리(`Ex-Tool/`)에서 아래 명령어를 실행합니다:
```bash
sudo .venv/bin/python3 Scanning/packet_sniffer.py
```

### 2단계: 네트워크 인터페이스 선택
프로그램이 시작되면 시스템에서 활성화된 사용 가능한 네트워크 인터페이스 목록을 보여줍니다.
```text
[*] 사용 가능한 네트워크 인터페이스 목록:
----------------------------------------------------------------------
  [1] lo0        | IP: 127.0.0.1       | MAC: 00:00:00:00:00:00
  ...
  [10] en0        | IP: 172.29.72.27    | MAC: 50:ed:3c:35:6a:4a
----------------------------------------------------------------------
[?] 스니핑할 인터페이스 번호 선택 (기본: en0): 
```
*   현재 사용 중인 인터넷망(Wi-Fi 또는 이더넷 등)의 인터페이스 번호를 선택합니다. (예: `10`을 입력하거나 엔터를 쳐서 기본 활성 인터페이스 사용)

### 3단계: 프로토콜 필터 선택
스니핑할 목적에 맞게 BPF 필터를 적용합니다:
```text
[*] 캡처할 프로토콜 필터 선택:
  [1] ALL  - 모든 패킷 수집 (기본값)
  [2] TCP  - 웹 트래픽, SSH, 데이터 송수신 등
  [3] UDP  - DNS, 스트리밍 등 비연결형 프로토콜
  [4] ICMP - Ping, 네트워크 진단
  [5] DNS  - 도메인 네임 질의
  [6] HTTP - 평문 웹 사이트 요청/응답
[?] 필터 번호 선택 (기본: 1): 
```
*   해당하는 번호(예: `1`)를 입력한 후 엔터를 누르면 패킷 모니터링이 시작됩니다.
*   **중단(Exit)**하려면 터미널 창에서 **`Ctrl + C`**를 입력하세요. 수집된 최종 세션 보고서가 대시보드로 렌더링됩니다.

## 4. 실습 시나리오 (Lab Scenarios)

### 시나리오 A: DNS 질의 패킷 수집
DNS 프로토콜(UDP 53포트)의 요청과 응답 구조를 직접 확인합니다.

1.  패킷 스니퍼를 실행한 뒤, 필터로 **`5` (DNS)** 또는 **`1` (ALL)**을 선택합니다.
2.  새로운 터미널 창을 열고 임의의 도메인으로 DNS 질의 명령을 전송합니다:
    ```bash
    nslookup google.com
    ```
3.  스니퍼 화면에 아래와 유사한 보라색 패킷 로그가 실시간 출력되는지 관찰합니다:
    ```text
    [17:01:22] [  DNS   ] 172.29.72.27:54321 -> 8.8.8.8:53 | Query: google.com (74B)
    [17:01:22] [  DNS   ] 8.8.8.8:53 -> 172.29.72.27:54321 | Response: google.com is at 142.250.190.46 (90B)
    ```

### 시나리오 B: TCP 3-Way Handshake 관찰
TCP 연결 수립 및 해제 과정에서 사용되는 Flag(SYN, ACK, FIN, PSH)의 상태 변화를 알아봅니다.

1.  스니퍼를 실행하고 필터로 **`2` (TCP)**를 선택합니다.
2.  새로운 터미널 창을 열고 포트 80(평문 웹 포트) 웹서버에 임의 연결을 맺습니다:
    ```bash
    curl http://example.com
    ```
3.  터미널 상에 찍히는 초록색 TCP 플래그들을 관찰합니다:
    *   `[SYN]`: 클라이언트의 연결 요청
    *   `[SYN|ACK]`: 서버의 연결 허용 및 확인
    *   `[ACK]`: 연결 수립 최종 확인 (3-Way Handshake 완료)
    *   `[PSH|ACK]`: 데이터 전송 세그먼트

### 시나리오 C: 평문 민감 정보(자격증명) 노출 감지
암호화되지 않은 프로토콜을 통과하는 정보가 네트워크 도청(Sniffing)에 얼마나 취약한지 확인합니다.

1.  스니퍼를 실행하고 필터로 **`6` (HTTP)** 또는 **`1` (ALL)**을 선택합니다.
2.  새로운 터미널 창에서 계정 정보(`username`, `password`)를 포함한 POST 요청을 전송하는 시뮬레이션을 돌립니다:
    ```bash
    curl -X POST -d "username=student_id&password=SuperConfidentialPassword123" http://example.com
    ```
3.  스니퍼 터미널에 강력한 **빨간색 경고창(⚠️ SECURE WARNING)**이 뜨며, 평문 텍스트 형태로 적나라하게 노출된 패스와 로그인 정보가 실시간 감지되는지 확인합니다:
    ```text
    ┌──────────────────────────────────────────────────────────────┐
    │ ⚠️  [SECURE WARNING] 평문 중요 정보 전송 감지!                │
    │ ├─ 발생 시간  : 17:04:11                                     │
    │ ├─ 경로       : 172.29.72.27 -> 93.184.216.34 (HTTP)         │
    │ ├─ 감지 키워드: username, password                            │
    │ └─ 페이로드   : username=student_id&password=SuperConfident...│
    └──────────────────────────────────────────────────────────────┘
    ```
4.  작동을 정지(`Ctrl+C`)하여 최종 **보안 분석 리포트(Security Alert Report)** 요약 통계를 점검합니다.

## 5. 문제 해결 (Troubleshooting)

### 🔴 `Permission denied: could not open /dev/bpf0` 에러 발생 시
*   **원인**: 스크립트를 관리자(root) 권한 없이 실행하여 네트워크 카드 드라이버에 접근하지 못한 상태입니다.
*   **해결책**: 명령어 앞에 반드시 `sudo`를 붙여 실행해 주세요.
    ```bash
    sudo .venv/bin/python3 Scanning/packet_sniffer.py
    ```

### 🔴 `ModuleNotFoundError: No module named 'scapy'` 에러 발생 시
*   **원인**: 활성화되지 않은 일반 시스템 파이썬 환경에서 실행했거나 가상환경에 라이브러리가 없는 경우입니다.
*   **해결책**: 가상환경 내에 패키지가 깔려 있는지 점검하고 경로를 명시하여 실행합니다:
    ```bash
    .venv/bin/pip install scapy
    ```

### 🔴 패킷이 캡처되지 않고 멈춰 있는 경우
*   **원인**: 선택한 네트워크 인터페이스 이름이 잘못되었거나(실제 트래픽이 흐르지 않는 가상 인터페이스 등) 가상머신 내부여서 브리지 모드가 잡히지 않았을 수 있습니다.
*   **해결책**: 인터넷 브라우저로 아무 웹사이트나 접속하여 트래픽을 유도해 본 뒤, 반응이 없다면 프로그램을 재시작하고 인터페이스 목록 중 IP 주소가 유효하게 적힌 인터페이스(예: en0)를 다시 지정해 주세요.

## 6. 화이트해커 노트 (White-hat Hacker Note)

*   **기밀성(Confidentiality)의 중요성**: 평문 프로토콜(HTTP, FTP, Telnet 등)을 사용하는 경우, 본 스니퍼처럼 간단한 스크립트만으로도 패킷 중간 탈취가 완벽하게 가능합니다.
*   **방어 전략**: 
    1.  **전송 암호화**: 모든 웹 연결은 기본적으로 HTTPS(TLS/SSL) 프로토콜로 대체해야 하며, DB나 커스텀 소켓 통신도 TLS 암호화 레이어를 거쳐야 합니다.
    2.  **보안 헤더 설정**: HSTS(HTTP Strict Transport Security)를 웹 서버에 활성화하여 강제로 브라우저가 HTTPS로만 접속하게 유도합니다.
    3.  **네트워크 보안**: 사설 가상 네트워킹(VPN), WPA3 무선 통신 규격 사용, 네트워크 세분화(Network Segmentation)를 적용하여 도청의 범위 자체를 격리해야 합니다.
